## 1. 已确认的输入，不是现成的 Pioneer 能力

- 本机插件源位于 `D:/Project/GitProject/dsh-manqu-pet`，当前 `package.json` 为 0.2.0、`dsh.client.platform = web`。这是 DSH Web bundle，不是 Codex 原生悬浮窗，也不是已存在的 Pioneer 插件协议。
- 复用对象：`.dsh-plugin/assets/pet.json`、`spritesheet.webp`（CodexPet v2 图集）、`client/atlas.mjs`、`client/index.mjs` 的播放器/交互以及 `src/state.mjs` 的纯逻辑。图集单元尺寸不是应用 UI 尺寸预算。
- 原宿主依赖 `jobs/agents/sessions/webServer`；`/manqu/state`、`/manqu/assets`、`/manqu/events` 是该插件在 DSH 下的 HTTP/SSE 路由，不直接视为 Pioneer 接口。原坐标逻辑只处理浏览器 viewport，不证明 Windows 多屏可用。
- `.dsh-plugin/client/index.mjs` 是源码；`.dsh-plugin/client.js` 是生成物，不手改。正式施工重新核对版本、哈希与 source/build 边界。
- 插件 `ASSET-NOTICE.md` 区分代码 MIT 与第三方满区素材，未证明素材可无限制再分发。首期优先本地指定资源兼容；未清权素材不默认进入公开安装包、素材 ZIP 或 Figma 上传，发布前另过权利/授权门。

源文件指纹、调查范围和未运行项目见[只读计划审计](../testing/manqu-pet-plan-audit-2026-10-01.json)。本轮未改插件、未启动 DSH，也没有完成副屏交互修复。

## 2. PET1 · 宿主、图集与基础交互

**目标：**为 Pioneer 提供专用薄适配层，复用满区而不是重写一套形象；不为一个宠物先建设完整 DSH/Cordis 或通用插件运行器。

1. 先做宿主呈现探针，明确应用内伴随层与独立桌面悬浮窗的取舍、焦点/命中区、窗口边界及资源加载方式。**独立悬浮窗不是当前已经存在或已经承诺实现的能力**；如选用，其 native 生命周期与多屏方案须写入聚焦宿主合同。
2. 提供可发现的启用/隐藏/恢复入口，用户显式启用，不新增系统自启动。验证待机、视线跟随、点击、拖拽及菜单的可用子集；键盘可操作、隐藏后能找回。基础交互不申请任务执行或读取工作区权限。
3. 本地资源按固定 manifest/文件白名单解析、限量读取；若选择插件目录，只授予已选择并校验的资源目录只读范围。拒绝路径穿越、任意文件读取、远程资源和任意脚本/Node 半侧执行。不靠连接正在运行的 DSH 服务才能展示宠物。
4. 配置、位置和隐藏状态采用 Pioneer 自己的命名空间/版本；不读写用户现有 DSH localStorage、Codex overlay bounds、DSH profile 或全局插件配置。
5. 复用 WC1 的主窗关闭/退出/重开协调：宠物不成为第二个会话存储写入者，也不替代托盘的唯一可发现重开入口。若有辅助窗口，明确与主窗口区分；退出/卸载时清理 RAF、timer、订阅、输入监听和辅助窗，重复启用或重开不得重复挂载。
6. 保留 contextIsolation、sandbox、CSP；仅提供必要、可校验的专用资源/配置接口，不暴露通用 IPC、任意路径、窗口方法分发或 `window.require`。

**依赖：**宿主/资源调查可与既有只读准备并行；原生窗口集成在 WC1 生命周期稳定后施工。PET1 不等待 M4 的真实运行器，不阻塞 M2 独立收口；同一副本的构建/E2E仍单排。

## 3. PET2 · 真实状态事件适配

- 在 M3-B/M4 的权威事件合同存在后，另做显式会话/任务范围的白名单、只读事件映射；不照搬 DSH 的全会话聚合或 2 秒轮询。快照、事件来源、关联身份、修订/顺序、终态与卸载订阅先形成合同。
- 当前无运行器时仅承认闲置/未连接及用户触发交互。保存草稿、切换布局、窗口最小化或资源加载成功都不是运行、批准或任务完成事件。
- 运行/等待批准/失败/完成只能来自真实 main 权威状态；断连、未知、过期或取消不得伪造成功。满区动作不授予权限、自动批准、重放任务或修改文件，不能成为唯一状态/错误提示。
- 事件默认只带必要的本机状态元数据；不自动读取消息正文、路径、Diff、文件内容或所有会话摘要。摘要气泡/跳转若需要，另定明确范围和脱敏合同，文本安全渲染，不新增外发或模型调用。
- PET2 的真实运行证据随对应 M3/M4 切片验收；不因 PET1 图集或模拟事件通过，就关闭 PET2 或声称 Harness 已接通。

## 4. 原设计与装饰预算不变

- 满区适配是独立扩展要求，不替换 Hazel × Claude 的配色、字体、组件、导航或 Apple HIG 窗口层。原欢迎装饰的 88/64px 槽位、48px 配饰、至少24px文字安全距及每视图最多一张继续有效。
- 宠物显示时须明确与原欢迎图的去重/互斥；不得以“插件”为由叠加第二个装饰主体、遮挡输入/窗口三点或把活跃会话、权限、错误工作面改成插画区。若独立悬浮形态与现预算冲突，先过设计决定门，不能默认豁免。
- 默认安静，尊重降低动效；不照搬原插件的自动跳跃庆祝、随机散步或结果摘要气泡。隐藏/最小化/卸载要暂停或停止非必要绘制/订阅，不抢焦点。用户手动互动与任务状态反馈分开。

## 5. 完成门与证据分类

| 层级 | 必须证明 |
| --- | --- |
| Contract | manifest/图集校验、路径和体积限制、专用 IPC 可信 sender/载荷、配置迁移、重复挂载与清理；PET2另测事件范围/乱序/未知/撤销，无执行权限 |
| 真实 Electron | 本地离线图集实际加载、启用/隐藏/恢复、拖动/点击与键盘、位置重启恢复、关闭/退出/重开无泄漏；现有保存/关闭失败路径不退化，fixture/profile隔离 |
| Windows 真机 | 主/副屏、负坐标与混合 DPI、跨屏命中与边界；如实现悬浮窗，验证穿透/焦点/最小化/全屏/任务栏行为；分别保留真实点击/拖拽与可恢复性证据 |
| 设计与可访问性 | 与欢迎图互斥、原预算、640/900/1280/1440与窄/短布局、三点不被挡、降低动效、200%/强制颜色/读屏；Figma/DOM尺寸不替代真机验收 |
| 集成交付 | 新候选身份、聚焦测试、完整 `pnpm check` 的最终退出码/打包、独立审阅及未覆盖项；插件源如获准修改，另走其原生 check/build 校验 |

PET1 纳入本机体验扩展的基础兼容待验项，PET2 单列随真实任务链收口，避免将远期事件接入变成 M2 或静态宿主的循环前置条件。本轮只新增计划，不复制素材、部署/启用插件、修改 Pioneer 工程输入或重跑工程门禁。
