## 2. 实际接线

1. main层复用既有renderer保存队列与窗口close coordinator，新增app级close/quit/reopen意图、同一sessionStore与accepted-save tracker。红点/普通原生close仅关闭窗口，最后窗口关闭保留进程；托盘/第二实例可重开，明确退出才结束进程。
2. app ready/catalog初始化前的重开请求合并；每次重开绑定新可信顶层webContents，旧窗口关闭后卸载状态监听与固定IPC。没有第二个会话写入者；托盘失败保留可操作窗口并解释，不静默把红点变成quit。
3. preload公开6条固定、无payload窗口API。main校验可信顶层sender与精确参数；没有通用方法、bounds、window ID、路径、命令或Electron事件对象泄漏。
4. main原生事件回读focus/minimize/maximize/fullscreen，renderer不乐观模拟成功。绿点切换原生全屏，独立窗口菜单提供最大化/还原；从全屏退出恢复进入前普通边界或最大化状态，并重新检查当前显示器workArea。
5. 左上红/黄/绿12px圆点、32px交互目标、40px窗口层，位于loading/error/工作面之上；窗口控制颜色独立于业务危险/成功色。空白caption交给原生拖拽区，按钮和菜单no-drag，不用DOM双击冒充OS标题栏行为。
6. Windows `query-session-end`进入独立`system-ending`意图，共享安全保存门；用户退出为`user`意图，失败/取消均清除。当前代码延迟会话结束，不证明真实Windows继续结束或强制期限内一定保存。

## 3. 真实故障与修复

- 三点尚未接线时，真实Electron红测试因找不到“关闭窗口”失败，原日志`tests/wc1-runtime-red-2026-10-01.log`保留。
- 首次接线发现Windows `enter-full-screen`事件早于`isFullScreen()`状态更新；同步读取使绿点留在busy。先加事件先于flag的Contract red，再改为下一tick回读实际状态，随后真实全屏往返通过；不按事件名伪造状态。
- 独立审阅发现renderer断连不清quit intent、旧保存回调可能关闭replacement renderer。断连现在使关闭协调、barrier generation、deferred saved-close与quit intent失效；新renderer不会继承旧关闭权限。
- 崩溃恢复暴露hydration读到未完成写入之前快照的问题；`store.load`现在先等待app级已接受写入settle。真实crash→reload测试先存会话再写新草稿，读回恢复后的实际草稿、窗口状态，并证明之后普通close仍不退出。
- Playwright 1.62的Page在crash后永久失效（本机`playwright-core/lib/coreBundle.js`的`_didCrash`）；本测试使用真实Electron `webContents.executeJavaScript`回读恢复DOM并调用实际窄preload接口，**不是模拟DOM或模拟crash**。保留诊断/失败日志，不通过延长超时掩盖。
- 全屏恢复失败时保留原快照，再次进入不覆盖未消费恢复数据；新增Contract red→green。保存失败通知清退出意图但保留可重试关闭对话框。
