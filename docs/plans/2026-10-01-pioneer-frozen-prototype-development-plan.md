## 1. 已定下来的产品方向

Pioneer 的两条主线一起推进：**让用户组织和操作 Agent 的交互系统**，以及**让任务真的能运行的 Harness**。不是只把旧界面换皮，也不是先把所有面板做完才接模型。

- 首页沿用 Jellyfin 式媒体库：工作区海报、搜索、最近会话、项目内新建与恢复。
- 会话工作区借鉴 **Adobe Premiere Pro** 的面板组合：模块是内容／能力，面板是可见实例，布局是面板的排列。
- 对话是默认完整主面板：工作区身份、欢迎建议、消息、意图／授权、进度与输入属于它的内部状态。它可以移动，不锁死左／右列。
- **不恢复专注／审阅／交付分页或模式按钮。** 改动、上下文、能力、产物、验收和日志按需要加入。
- 新结果更新对话里的入口和计数；用户点击才打开、切换或定位。后台任务不改布局、不抢标签、不拉走用户正在读的位置。
- Hazel × Claude 的银灰、藏蓝、薄荷、中文阅读感和克制装饰保留。冻结稿定方向与行为，不锁死每个像素、断点或卡片数量。
- Windows 宿主采用红绿灯和 macOS 式窗口逻辑；HIG 只补窗口操作，不取代本应用规范。
- 装饰预算不变，以已有素材复用、替换和稀疏分布增加变化；`dsh-manqu-pet` 通过薄适配接入，不再增加第二套常驻助手界面。

设计／原型参考：[F9 验收](../research/figma-make-final-acceptance-2026-10-01.md)、[源码归档](../design/make/frozen/2026-10-01-f9/README.md)、[Figma 分工](../design/figma-archive-make-handoff-2026-10-01.md)。Figma Design 管可编辑规范与资产；Make F9 管交互参考；Pioneer 代码与真实验证管实现结果。

## 2. 工程底座怎么选

| ---------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |

| Make F9          | 对话构图、海报与会话入口、面板树操作思路、结果卡与显式打开行为、窄窗呈现、交互细节                                 | 演示数据、计时器、假 runner、localStorage、默认权限、假窗口／托盘和 CDN 字体不作为工程底座 |

**保留现有 Electron 构建链。** 不把 Make 的 `package.json`、Vite 配置、Figma 插件或脚本塞进根工程。拆出 React view／样式和纯布局行为，接当前 Zod 合同与固定 preload API。是否使用 Tailwind 等样式工具是局部实现选择，不为复制原型顺便迁移整套构建。

已有 RuntimeSession bootstrap 只初始化快照，`modelAccess/toolExecution/fileMutation` 均为 false。Make 的 `store.ts` 虽删除了意图签署，**当前代码仍保留旧意图修订、显式确认和 READY 合同**。P0/P1 适配它，而不是把它恢复为每项任务的强制关卡：意图摘要用于可选澄清，人工确认针对权限扩大、破坏性动作与发布。READY 不等于工具／写入许可，不需要另开审阅页面。

## 3. 原型拆成哪些工程模块

| 模块                           | 展示职责                                         | 真正的数据／操作来源                                             |
| ------------------------------ | ------------------------------------------------ | ---------------------------------------------------------------- |
| Library／Tabs                  | 工作区海报、搜索、最近／打开／关闭会话           | main 扫描结果、工作区身份和本机会话库                            |
| Conversation                   | 欢迎、草稿、消息、意图、授权、运行摘要、结果入口 | 会话域与意图域；后续订阅带 session/run 身份的运行事件            |
| DockWorkbench                  | 标签组、拆分／合并／移动／关闭、键盘调整、窄窗   | 每会话布局树；只接收用户布局操作，不能执行任务                   |
| Context                        | 已选文件／引用、建议、过期原因、来源             | 明确选择的只读引用和实际发送清单，不隐式把整个目录塞给模型       |
| Capabilities／Permissions      | 当前能做什么、为什么不可用、这次允许什么         | runner 能力报告和 main 授权记录，不能由 renderer 开关赋权        |
| RunLog                         | 开始／输出／请求权限／停止／失败与终态           | 权威运行事件，有顺序与来源，不用计时器假推进                     |
| Changes／Artifacts／Acceptance | Diff、预览、版本、应用和核验记录                 | 实际文件差异、产物索引、校验结果、用户决定；不套“全都成功”默认值 |
| Window／Pet                    | 原生窗口控制、陪伴和避让                         | Electron 窗口／托盘 API；后续薄插件适配，不拥有任务权限          |

会话／任务／布局状态拆开：切标签不换任务身份，关闭面板不停止任务，关闭会话标签不删除记录。UI 订阅数据，而不是 UI 状态反过来假造执行成功。

## 4. 开发顺序与每片的完成条件

以下 P0–P5 是实施切片，不是新的里程碑编号；对应 M2/M3/M4 等阶段的证据仍回到 ROADMAP。P0、P1 已完成，P2–P5 按下述完成条件推进。

2026-10-03 已保存 1467 项复工输入的可恢复 ZIP 与逐文件哈希。复工基线曾在 lint / typecheck 失败；补齐独立会话合同后完整 `pnpm check` exit 0：194 Contract、210 冻结 Prototype、9 Real Electron E2E 与最终 package。没有删候选或放宽校验。见[复工记录](../testing/development-resumption-2026-10-03.md)、[P0 收口](../testing/p0-integration-closeout-2026-10-03.md)和[组件／去向映射](2026-10-03-p0-integration-map.md)。

### P0 · 保住现场，统一合同和可复现参考

1. 记录 main／本地／dirty 三份边界，为已有改动建立可恢复快照；从 main 选择整合底座，逐模块移植 Workbench，不覆盖最新 M3 流程。
2. 用已归档 F9 建立组件／行为对应表；核对字体、图片来源和现有资产预算。字体本地化，封存 ZIP 不解包成活动规则。
3. 对齐文档：旧三模式、按模式存储和刚性断点条款不再执行，安全／权限／可读性条款保留；核对 ROADMAP 与 main 已合入代码／证据的差异，不机械重做已通过的切片。
4. 对选定工程修订建立测试基线；既有门禁是否可继承有具体修订依据，新接线后的构建重新验证。

**完成条件：** 唯一实现候选、未合并内容都有去向；Make、main 与 Workbench 的差异可查；没有丢文件，也没有把历史 PASS 当当前构建通过。

### P1 · 第一片：能保存与恢复的任务会话

2026-10-03 已完成：生产 main / preload / App 接通，会话草稿／消息／意图／单布局与产物视图可保存和恢复，取消旧三模式。新完整 `pnpm check` exit 0：200 Contract、21 Real Electron E2E 与最终 package；冻结 Prototype 门同时通过。见[P1 收口](../testing/p1-session-closeout-2026-10-03.md)。P0 门仍保留为此前输入的历史证据。

把首页→新建／恢复会话→完整对话→可选意图澄清／修改／取消→本地会话初始化 连成真实 Electron 流程。先做到一个可用的对话面板和显式打开的上下文／日志入口，其他内容保持真实空态。

- 主 UI 去掉旧三模式；Library 的项目与新 Session 建立清楚身份映射，不直接覆盖两个不兼容的 Tabs reducer。
- 把现有 M3 revision／bootstrap 状态与可选意图摘要放进会话并持久化；不保留所有任务都要签署的启动门。草稿、消息、布局、选择的产物和任务身份互相隔离。
- **持久化升版迁移**：从旧 v3 的当前 `layout` 选出会话单一布局；其余 `dockLayouts/savedLayouts` 作为可恢复历史数据保留，不直接丢弃。未知／损坏格式保留原件、给恢复入口，不因 Zod 失败清空记录。
- 暂不连接模型／工具，明确显示未连接；不会用 Make 假回复填补空白。

**完成条件：** 切换两个会话、关闭重开、重启恢复草稿／意图／布局；初始化只生成合法快照，不赋予执行权限。schema 迁移、隔离、保存失败和 main→preload→renderer E2E 有证据，工作区 fixture 不变。

### P2 · 尽早接通第一条真实只读 Harness 任务

P1 之后就进入，不等待完整面板库、桌宠或全部微动效。复用 Pi Agent Harness；先核对当前官方包/API 和宿主接法，再确定固定版本与适配接口。

- 选一个人工许可的测试工作区和确定目标，例如“读指定文件并说明模块职责”。限定读取路径与工具白名单；不开放 shell、写文件、浏览器或远程推送。
- 先确认 provider、鉴权方式和实际发送范围；未经许可不发送个人工作区，不改用户全局模型／provider 配置。
- main 掌管运行对象和授权，preload 提供小接口；renderer 提交请求、订阅事件，不能直接调用文件系统或 provider。
- 事件至少含 sessionId、runId、revision、顺序和来源；覆盖启动、流式输出、工具请求／结果、等待权限、停止请求、停止确认、失败和终态。断连是“状态未知”，核对后再显示结束。
- 装配本轮必需引用／能力，记录上下文来源和发送量；不要把全局技能全文、全部历史和所有文件一起塞入。

**完成条件：** 一条真实模型／只读工具链在 Electron 内跑通，能看到来源、停止和结果；fixture 未修改。可控测试适配器用于自动测试，实际授权 provider 另做真实运行证据，二者不互相顶替。

### P3 · 完整面板体验与真实内容接线

与 P2 后半段并行，但不能拖住首条只读任务。

- 完成显式入口的“关闭→打开、隐藏标签→切换、已显示→定位”，拆分／移动／合并／键盘替代和每会话保存。
- 上下文、能力、日志、文本／Markdown／表格产物逐类接真实数据；尚不支持的格式提供明确打开／导出选项，不给假预览。
- 会话间／运行间事件不会串流；结果产生不自动开面板、不改排列、不抢阅读滚动。窄窗临时呈现不破坏宽窗布局。
- 从 F9 借用 view 和纯布局思想，不沿用它宽松的 `any` 数据、假数字或静态可用能力。

**完成条件：** 新结果出现时布局不变；用户可用鼠标或键盘按需查看所有已支持内容；刷新／重启恢复。代表性窄／常规／宽窗口和长中文／长路径可读，不把某个像素断点当目标。

### P4 · 写入与命令：单独的风险切片

只读链通过不自动开放写入。先定目标路径、允许的命令、授权范围与时效、文件最新版本检查、快照／回滚和停止后的部分完成状态，再逐项启用。

- 保留修订与一次性授权关联；过期、目标变化或 revision 变化不能沿用旧许可。
- 分清代码修改与产物生成。部分 Diff 接受／退回／重新生成后，旧测试结论失效；不能无条件套原型“审阅→应用→验收→交付”的流水线。
- “接受 Diff”与“写入磁盘”分别记录；主进程拒绝越界／符号链接逃逸／过期文件，写入失败不显示成功。
- 回滚只处理本次受控变化，不恢复或删除用户并发新增内容。人工标准只有人工确认才通过。

**完成条件：** 在隔离 fixture 中实际写／拒绝／取消／失败／回滚有完整证据，文件不变量和权限时效通过；真实个人工作区使用另经授权。

### P5 · Windows 成品体验、桌宠与打包

窗口、离线字体、关键遮挡可以在 P1–P3 并行修；整体收口放在真实任务链之后。

- 红绿灯接真正的关闭／托盘、最小化、最大化／全屏及恢复；处理托盘不可用、多窗口、关闭保存失败和重启恢复。无声退出／假隐藏不能冒充关闭成功。
- 字体随包分发，验证中文、字重、代码回退和离线加载；Windows IME、键盘焦点、高 DPI、多显示器、强制颜色和减少动效实际检查。
- PET1 复用 `dsh-manqu-pet` 的合法资源与交互，做薄宿主；避开输入、按钮、证据与表格，紧张时收边。PET2 只在事件合同稳定后订阅权威状态，不读其他宿主／会话的数据，不给桌宠执行权限。
- 资产去重与复用不增加原装饰预算；业务内容优先，不把 F9 桌宠遮文字作为既定视觉规范。
- 打包 smoke、独立审阅和演示脚本包含真实任务、拒绝／失败／恢复，不只有漂亮成功页。

**完成条件：** 可安装 Windows 构建、离线字体、真实窗口和任务恢复有证据；桌宠可收起且不挡核心内容。已授权阶段按治理流程交接，不自动发布。

首个交付不是“所有页面都像截图”，而是：**从媒体库进入一个能保存、能澄清目标、能恢复的真实会话；紧接着让这个会话跑通第一条可观察、可停止的只读任务。**
