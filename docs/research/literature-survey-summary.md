## 第一部分：开题报告「国内外研究现状」规范学术述评正文稿

### 1.1 国外前沿与大厂工业界实践：从黑盒聊天走向空间交互与轻量运行时

随着大语言模型（LLM）从被动的单向“文本预测器”向具备环境感知、自主规划与工具调用能力的“行动中枢”演进，国际学术界与大厂工业界围绕智能体（AI Agent）的人机交互范式与工程底座展开了剧烈变革。

**首先，在交互形态维度，大模型正经历从“单一线性对话流”向“空间化工作区与多模态 GUI 具身操作”的范式跃迁。** 长期以来，主流大模型桌面应用普遍沿袭 ChatGPT 开创的“左侧历史会话列表 + 中间对话气泡”的固定三栏布局。然而，顶级人机交互会议 ACM UIST 2023 收录的 **Sensecape 研究（Suh 等, 2023）** 指出，单向滚动的线性对话流在面对复杂、多步骤的任务探索时，会导致用户陷入严重的“认知通道化”（Cognitive Tunneling），极易丧失全局视野。为此，Sensecape 形式化提出了“抽象阶梯”（Abstraction Ladder）与多层级空间化画布理论，论证了将信息解耦为宏观全局视图与微观操作细节的必要性。2024 年，**Anthropic 官方发布 Computer Use（Claude 3.5 Sonnet）**，使大模型具备了直接感知屏幕像素、点击光标与击键的操作系统级交互能力。然而，在权威的操作系统盲测基准 **OSWorld** 上，Claude 3.5 Sonnet 的自主任务解决率仅为 **14.9%**，且在复杂的连续操作中极易出现状态误判与死循环。Anthropic 官方技术报告明确指出，目前的像素级自主操作极度脆弱，必须建立严格的“人类监督（Human Supervision）”与动作可逆（Reversibility）机制。这表明，构建以人为中心、具备状态可视化与执行前审计的交互系统，是智能体走向实用的先决条件。

**其次，在工程底盘（Harness）维度，行业正在经历从“重型情景规则堆砌”向“渐进式披露与轻量标准化”的深刻反思。** 过去两年间，以 LangChain、WorkBuddy 为代表的框架倾向于通过厚重的 System Prompt 封装角色设定、长篇流程食谱（Recipes）与细碎防范规则。然而，**OpenAI 官方在最新发布的技术文献《Rethinking Skills and Prompts for GPT-6 Astra》（OpenAI Developers, 2026）** 中提出颠覆性论断：针对弱模型设计的繁琐指令堆叠反而会劣化高推理能力模型的表现，引发严重的“上下文膨胀（Context Compaction）”与路由降级；OpenAI 明确倡导**“渐进式披露（Progressive Disclosure）”**架构，强调技能定义必须保持极简，根文档仅作为轻量路由层按需加载。与此呼应，**Anthropic 在《Building Effective Agents》（Schluntz & Zhang, 2024）** 研究报告中旗帜鲜明地呼吁“拒绝过度复杂的黑盒多 Agent 框架”，倡导回归最简、可控的透明工作流，并强调依赖外部环境提供的客观真值反馈（Ground Truth Feedback）。同时，**OpenAI Swarm（2024）** 将多智能体编排高度凝练为 Routine（例程）与 Handoff（控制权交接）两大无状态原语，证明了轻量解耦协作的高效性。

**最后，在协议标准与执行可靠性方面，大厂正在全力构筑高确定性基础总线。** **Anthropic 联合开源界推出的 Model Context Protocol（MCP, 2024）** 开放标准，确立了 Prompts、Resources、Tools 三大核心原语与基于 JSON-RPC 的客户端-服务器解耦架构，有效化解了智能体对接异构工具的 $M \times N$ 孤岛危机；**OpenAI 推进的 Structured Outputs 规范（2024）** 则通过上下文无关文法（CFG）约束采样与状态机剪枝，在数学级别保证模型输出 100% 契合 JSON Schema，杜绝了参数幻觉。此外，普林斯顿大学在 ICLR 2024 Oral 论文 **SWE-bench（Jimenez 等, 2024）** 中对 2,294 个真实 GitHub Issue 进行了大规模实证，证明未配备工程 Harness 的原始最强模型解决率低于 **5%**。这从科学上确立了：决定 Agent 任务成败的关键在于上下文编排、环境反馈与工具执行循环（即 Harness 工程），而非单纯的模型参数本身。

### 1.2 国内学术界人机交互与国家战略规划：聚焦混合主动协同与国家未来产业

在国内学术界与产业政策层面，智能体与人机协同交互已被确立为国家级战略制高点与核心计算机研究议题。

**在国家战略与行业智库规划方面，** 中华人民共和国国务院早在 2017 年印发的**《新一代人工智能发展规划》（国发〔2017〕35号）**中，就将“人机混合增强智能”、“自主协同控制系统”与“自然人机交互”部署为关键攻关方向；2024 年 1 月，工业和信息化部、教育部、科技部等七部门联合印发**《关于推动未来产业创新发展的实施意见》（工信部联科〔2024〕12号）**，在“未来信息”标志性领域中明确部署突破通用人工智能（AGI）、智能体（AI Agent）以及新一代智能人机交互系统，打造人智协同的高效工作空间。2025 年 6 月，**中国信息通信研究院人工智能研究所发布《智能体技术和应用研究报告（2025年）》**，正式将智能体定义为“大模型原生应用的核心形态”，并指出智能体系统由“大脑规划决策”与“工具行动执行”双轮驱动，亟需通过标准化协议、轻量化工具接口与意图核验机制破解不可控落地瓶颈。

**在学术界理论与系统工程演进方面，** 我国计算机与数字媒体领域的学者针对人机协同与代码智能体开展了深层次探索。在人机交互范式层面，**张小龙、程时伟等在《中国科学: 信息科学》（2018）** 发表的经典论文《智能时代的人机交互范式》中指出，人机交互已由传统基于 WIMP 的“主从指令式”迈入“混合主动协同式（Mixed-Initiative Collaboration）”，系统必须支持人与智能体互为认知伙伴、双向对齐意图并动态交接控制权；**陶建华、喻纯等在《中国图象图形学报》（2022）**《多模态人机交互综述》中进一步指出，未来交互的核心在于设计高效的模态组合，通过多面板自适应呈现大幅降低用户的认知负荷。在可解释性与信任机制层面，**丁一、陈为等在《计算机辅助设计与图形学学报》（2026）**《大语言模型可解释性研究综述》中强调，用户对黑盒模型的信任源于交互过程的可视化呈现与显式引导，界面是让模型决策具备可控性与可验证性的唯一桥梁。

在软件工程与智能体可靠性层面，北京大学高可信软件技术实验室**董益宏、金芝、李戈等在《软件学报》（2026）**《基于大语言模型智能体的代码生成综述》中指出，代码智能体已向全生命周期工作流与沙箱闭环演进，上下文污染治理与工具解耦是其落地的必由之路；而**李戈、彭鑫、谢涛等国内八位顶尖学者在《软件学报》（2023）** 联名发表的特邀论文明确指出，大模型作为基于自然语言交互的人机协同工具，其最大技术矛盾在于“概率模型的内生不确定性”与“软件工程高可靠决策需求”之间的鸿沟，必须通过结构化检验与显式交互反馈闭环建立系统级引导环境；针对图形界面智能体的长程任务失效问题，**卢小芬等在《软件学报》（2027/2026）**《基于世界模型自校准的智能体终身学习方法》中深入揭示了开放 GUI 中“状态转移幻觉”导致规划崩溃的根源，并创新性地提出 System-1（快速执行）与 System-2（监督检验）解耦的双层认知架构，论证了基于反事实因果归因进行状态回溯与动态重规划的必要性。

### 1.3 现有研究局限与 Pioneer 课题研究空白 (Research Gaps)

综合国内外文献与工业界实践，当前智能体交互系统仍存在三大突出研究空白与工程瓶颈：

1. **交互层呈现单一化与认知通道化**：市面绝大多数桌面 Agent 依然固守单一文本对话框与常驻侧边栏，导致项目一多难扫描、横向画幅被挤压、交互缺乏视觉实体映射，完全无法满足现代多项目工程中阶段切换与全局审阅的需求；
2. **Harness 层规则冗余与上下文污染**：传统工程习惯于在 Prompt 中强加成百上千行的情景规则与细碎封装，挤占了强基座模型的自主推理空间，且未能利用现代 KV 缓存（Prompt Caching）进行工程化优化；
3. **协同安全性与状态审计机制缺失**：多数系统要么完全由模型黑盒盲目改动本地文件，要么频繁弹出琐碎弹窗打断工作，缺乏“执行前意图结构化核对、执行中状态持续透明、涉及磁盘破坏性操作先预览 Diff 并提供可逆回滚快照”的高可靠机制。

**Pioneer 课题切入点**：本项目立足数字媒体技术专业本位，紧扣国家未来产业规划，践行**「一切皆 UI」(Everything is a UI)** 核心哲学，以**「模块化交互系统」**（浏览器级 Tabs + 媒体库海报墙 + Dockview 可停靠工作区）与**「轻量 Harness 工程」**（渐进式披露上下文 + Zod Schema 原子工具解耦 + 规范接入 Pi Agent Harness 底座）双主线协同推进，并在相同模型与任务下开展严格受控的基准对比实验，系统填补上述交互与工程空白。

### 第 2 页 · 选题背景（一）· 交互层痛点与现有方案缺陷

*   **PPT 核心文本映射**：
    *   主标题：主流 Agent 应用仍依赖侧边栏管理项目与对话，内容一多就难找、难读、难切换。
    *   痛点总结：`01 难扫描`（缺少视觉特征）· `02 占空间`（侧栏挤压横向画幅）· `03 自定义程度低`（布局固定无法随任务阶段调整）。
    *   对照案例：Codex（纵向堆叠、靠文字辨认）、Claude Code Desktop（列表变长、切换成本剧增）。
*   **深度学术文献支撑**：
    1. **Sangho Suh 等 Sensecape（ACM UIST 2023, EN-09）**：实证研究证实传统单向滚动的聊天气泡（Chat Stream）会导致严重的“认知通道化”（Cognitive Tunneling），用户在复杂多任务交互中极易迷失方向；论文提出的“抽象阶梯（Abstraction Ladder）”理论指出必须建立多层级空间化交互界面。
    2. **陶建华、喻纯等《多模态人机交互综述》（《中国图象图形学报》2022, CN-07）**：明确指出交互系统的发展瓶颈在于高认知负荷，必须通过多模态界面的自适应组合呈现，实现信息的高效压缩与空间解耦。
    3. **Ben Shneiderman 经典直接操纵理论 (Direct Manipulation, 1983)**：界定对象持续可见、动作物理化可逆是消除认知摩擦的关键。侧边栏文本列表严重违背直接操纵原则。
*   **答辩引述论点（面对评委）**：
    > “正如人机交互顶会 ACM UIST 2023 在 Sensecape 论文中所指出的，单向滚动的文本聊天框会导致严重的认知通道化，用户根本无法在长文本流中建立对复杂多工程的全局心智。目前市面如 Codex 和 Claude Code Desktop 普遍采用的常驻侧边栏，既挤压横向有效空间，又缺乏视觉特征。Pioneer 的首要突破，就是用空间化的海报墙与可组合工作区破除这一交互困境。”

### 第 3 页 · 选题背景（二）· Harness 层缺陷与过度约束反噬

*   **PPT 核心文本映射**：
    *   主标题：情景特化 Harness 持续堆积，开始限制高能力模型发挥。
    *   四个问题：`01 上下文污染`（长提示词挤占空间）· `02 能力重复`（场景反复封装）· `03 过度约束`（细碎规则剥夺模型判断力）· `04 复用困难`（能力与场景深度绑定）。
    *   对照案例：WorkBuddy（多类能力入口并存、过度封装）。
*   **深度学术与工业文献支撑**：
    1. **OpenAI 官方博客《Rethinking Skills and Prompts for GPT-6 Astra》（2026, EN-01）**：前沿工业界第一手实证断言：“当为智能体添加过多技能时，Codex 会被迫截断其描述以适应窗口，反而导致模型路由能力严重降级”；繁琐的细碎规则在弱模型时代是脚手架，在强模型时代却成为限制其发挥的枷锁。
    2. **Anthropic 研究报告《Building Effective Agents》（2024, EN-05）**：Erik Schluntz 等人严正指出，成功的关键不在于构建最繁复的系统，而在于最简透明架构；过度的黑盒 Agent 抽象框架反而会引入难以调试的混沌行为，应当优先采用清晰透明的极简工作流。
    3. **Anthropic 官方技术发布《Prompt Caching》（2024, EN-04）**：阐明静态前缀分层对齐机制，命中缓存可降低 **90% Token 成本** 与 **85% 端到端延迟**。情景特化 Harness 的动态长提示词随意变动，彻底破坏了静态前缀对齐，带来了巨大的经济与延迟惩罚。
*   **答辩引述论点（面对评委）**：
    > “不仅是交互，工程底层同样存在严重弊病。正如 OpenAI 2026 年针对 GPT-6 Astra 研究所指出的，随着基座模型推理能力剧增，以往靠堆叠几千字情景提示词的‘情景特化 Harness’已经发生反噬——上下文污染、技能描述截断导致路由失效、过度约束剥夺强模型思考空间。Pioneer 的主线二就是要给 Harness‘减负’，通过渐进式披露和 Prompt Caching 缓存对齐，为强模型保留纯粹的发挥空间。”

### 第 4 页 · 设计目标与主要内容 (双主线闭环架构)

*   **PPT 核心文本映射**：
    *   主标题：PIONEER：模块化 AI Agent 交互系统与 Harness 工程
    *   双主线协同：左侧交互系统（项目入口海报卡片、Tabs+Dockview 模块化工作区、执行过程持续可见）＋ 右侧 Harness 工程（轻量上下文按需组装、能力模块化 Tool/Skill 解耦、统一接入 Pi Agent Harness 规范）。
*   **深度学术与标准文献支撑**：
