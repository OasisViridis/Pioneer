# Pioneer 交付工作流

采用 TheMasterplan 的单一交付责任人、独立工作树、小批次 PR 与真实验证原则。本文件是仓库内可直接读取的操作入口；不依赖某台机器的 skill 安装路径。Issue 操作见 [issue-tracker](issue-tracker.md)，验证分类见 [TEST_INFRA](../../TEST_INFRA.md)。

## 开工检查

首次写入前，在任务记录填齐四项；可从当前授权和仓库事实推导的内容自行核实，不逐项请求人类确认。

| 项目 | 必须记录 |
| --- | --- |
| 任务来源 | 当前用户指令或执行 Issue；目标、授权范围与交付负责人。复杂工作用 Issue，小型同主题修复可沿用已有票。 |
| 工作区 | 最新 main 基线 SHA、独立 worktree 和 `codex/` 分支；检查未知修改及同任务的活跃 PR/写入者，不抢占现有任务。Git-only 不自动转换为 jj。 |
| 范围 | 本次用户结果、文件边界、排除项和实际所需的上游产物；缺信息先做不依赖它的调查。 |
| 验证入口 | `pnpm verify:repository`、完整 `pnpm check`，以及因改动适用的视觉、成品或人工验证。先检查未知命令副作用。 |

Issue 认领与远程回读按 issue-tracker 执行。同一执行单元只有一个写入者；不同单元可用独立工作树并行。主代理负责最终 Diff、提交与远程写入，子代理按明确文件边界协助。另一套交付系统已拥有该任务时退让，不建立竞争流程。

## 开工依赖与最终验收

- 原生 `Blocked by` 只记录当前实现必须消费的结果。写明所需接口/产物，不用阶段编号或“将来需要一起发布”代替真实依赖。
- 只读能力、Windows 安装/升级、只读实验可在各自输入就绪后推进；写能力、安全恢复、命令权限仍受各自前置约束。最终里程碑条件写在验收清单，不整票阻塞可独立交付的子范围。
- 上游实现须已合入 main，且所需结果有接受证据；文档决策使用已接受的决定链接。关闭 Issue、`ready-for-agent`、未经合并的 PR 均不能单独证明交付可消费。取消/重复关闭须重新判断。
- 下游以包含已接受结果的 main 为基线。原生依赖只是筛选信息，交付者在开工前核对具体结果；设计工具的自动门不替代这项核对。
- 一个负责人对应一个交付单元，不等于整个仓库永远只允许一个前沿。涉及同一接口或逻辑时先明确写入者，优先复用已有任务，不新增研究→决定→实现的固定票链。

## 实现与技术选择

每个小 PR 提供可验证的用户行为或必要安全不变量。较大的执行票用清单递进，不按每个文件、接口或错误码建票。完整性不足时保留未完成项，不能通过改名或闭票制造交付。

涉及新依赖、框架、通用状态机或传输时，在现有 Issue/PR 简短记录：当前需求；已有实现/成熟方案/最小自研的比较；一手来源及适用版本；选择与不支持范围；验证和撤回方式。常规可逆实现不因此增加审批。参考 [DORA 小批次](https://dora.dev/capabilities/working-in-small-batches/)、[Google 复杂度审阅](https://google.github.io/eng-practices/review/reviewer/looking-for.html)与 [YAGNI](https://martinfowler.com/bliki/Yagni.html)。

优先复用 Pi、现有 shared 类型、工具与测试。限制支持范围来控制复杂度，不以删授权、路径防逃逸、停止/恢复或坏档保护代替简化。外部平台自动化按实际收益逐步扩展，不额外阻塞无关产品交付。

## 验证、PR 与交接

1. 迭代中运行受影响检查；push 前运行完整 `pnpm check` 与 `pnpm verify:repository`，阅读最终 Diff。修改导致结果失效时复验；不反复运行没有新输入的同一套检查。
2. 使用[仓库 PR 模板](../../.github/pull_request_template.md)，说明目标、范围、验收、候选及风险；验证粘贴实际摘要并链接完整日志。当前 skill 包缺文件时先找可核验的协议源，不能编造门禁或把本地路径写进共享文档。
3. 列出实际实现者；由未参与实现的 Agent/人员对最终候选 SHA 技术审阅。把发现分成“合并前必须修复 / 建议本次修复 / 可以后续处理”，修复后重新核对受影响结论。
4. 创建 PR 后等待 CI，修复本次引入的失败。记录“已实现 / 已验证 / 等待人类批准与合并”；Agent 技术审阅不能代替人类批准。用户授权创建 Issue、提交、push 和 PR 不自动授权 merge、release 或破坏性操作。
5. Issue 的代码交付在合并且所需证据齐全后关闭；未合并时保留开放。历史已关闭但产物尚未合并的票，显式标记可消费条件，不让下游只看关闭状态开工。

同机并行验证时，为各检查进程设置不同的 `TEMP`/`TMP` 目录，或串行运行打包。当前 Electron Packager 会清空共享的临时根目录，仅隔离 worktree 不能防止并发构建互相删除临时文件；不因此修改产品逻辑或跳过打包门禁。

当前队列只维护在 [#9](https://github.com/OasisViridis/Pioneer/issues/9)；ROADMAP 只维护正式里程碑，规格保存行为与验收要求。一次事实保留一份版本化证据，其余入口链接，不复制会过期的测试计数、当前分支或 PR 状态。
