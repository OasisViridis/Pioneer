## 2. 设计主张

**安静的工作表面，明确的任务进展，可审阅的结果。**

1. 首页找工作区，单排 Tabs 切会话，对话承载任务；工具随任务展开。
2. 用文字层级、留白和细线组织信息，不用厚卡片、满屏色块或仪表盘装饰。
3. 藏蓝表达操作；银灰表达分隔；薄荷、香槟只辅助表达状态。工作区身份色不代表权限。
4. 一个决策区域一个主动作。正文说清事实、影响和下一步，拒绝含糊的“继续”和假成功。
5. 不引入 Claude 品牌橙、专有字体/图标、常驻历史侧栏、第二排全局导航、营销页巨幅标题、玻璃或渐变。

### 变量架构

- `Pioneer v2 / Primitives`：20 个原始色值 + 16 个数值，原始变量不出现在属性选择器。
- `Pioneer v2 / Color`：24 个语义色，全部 alias 到原始值；只提供已设计的 Light 模式，不伪造暗色支持。
- `Pioneer v2 / Geometry`：24 个语义尺寸，全部 alias；间距、圆角、边线、字号、控件高度分别限定 scope。
- 旧变量及旧原型状态变量不删除、不改值；只允许 v2 开发稿引用新体系。不能通过全局换色破坏旧原型证据。

## 4. 字体、尺寸与层级

中文 Noto Sans SC；拉丁界面可用 Inter；代码 JetBrains Mono。当前 v2 基础样式以 Noto Sans SC 和 JetBrains Mono 落地，Inter 不作为中文回退字体。路径/日志包含中文时，该字符范围明确回退 Noto Sans SC，不能容忍缺字；英文代码仍保留等宽字形。字体不随意替换为品牌专有字库。

| 样式                    | 字重             | 大小 / 行高      | 使用                                   |
| ----------------------- | ---------------- | ---------------- | -------------------------------------- |
| Heading/Large           | Bold             | 24 / 32          | 页面标题                               |
| Heading/Medium          | Medium           | 20 / 28          | 面板主标题、空态标题                   |
| Body/Reading            | Regular          | 15 / 24          | 对话与说明                             |
| Body/Default            | Regular          | 14 / 22          | 列表、权限范围、错误原因               |
| UI/Label                | Medium           | 14 / 20          | 按钮、导航、字段标签                   |
| UI/Small / Small Strong | Regular / Medium | 12 / 18          | 时间与非关键元数据，不承载唯一风险信息 |
| Code/Default / Small    | Regular          | 14 / 22、12 / 20 | 代码、路径与验证记录                   |

间距为 0/4/8/12/16/24/32/48/64。控件高 36px，紧凑命中区不低于 32px；需要容纳两行身份的全局 Tab 为 48px。按钮圆角 8px，卡片/面板 12px，输入组合区 16px。普通容器没有阴影；浮层使用一层 `0 8 24 rgba(33,42,59,.12)`。不叠阴影、不每行套卡。

## 5. 窗口与导航结构

```text
唯一全局行：工作区库 | 具体会话 Tabs | 新会话 | 全部会话 | 设置
会话工具栏：标题与工作区身份 | 专注 / 审阅 / 交付 | 面板与布局操作
当前内容：对话主轴 + 按需打开的上下文 / 能力 / 改动 / 产物
产物局部导航：预览 / 文件清单 / 验收记录
```

会话工具栏的布局选择不是第二套全局导航。关闭 Tab 不删除会话、不停止运行；面板显示/隐藏、拖拽、切布局均不授权任务。对话阅读列上限 840px；宽屏不是把文字拉满。

| 样本                                  | 开发稿规则                                                                                      |
| ------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1440×900                              | 3–5 个显性会话，宽内容+对话可并列，输入区固定在所属面板底部                                     |
| 1280×800                              | 最多 3 个显性会话；双栏各不小于 320px，不够则收纳低优先级工具                                   |
| 900×700                               | 工具栏允许换行；面板可临时收起，不能悄悄覆盖已保存布局                                          |
| 640×720；759/760px 边界               | 640–759px 单列对话+输入，工具通过显式“展开面板”入口临时打开；760px 边界不得丢入口或覆盖保存布局 |
| 1280×560（高度≤600px）                | 保留导航、输入、审批和错误动作；面板独立滚动，不以固定大空白挤走主操作                          |
| 200% Windows 缩放 / 高对比 / 降低动效 | 独立运行时验证项，不等同于缩小 Figma 画板；本轮只交付对应设计规则与待验收记录                   |

分隔条视觉线 1px，横向或纵向命中厚度不少于 24px，沿分栏方向覆盖可用边界；命中区不遮挡邻近控件。焦点可见，方向键调节、Home/End 到受限端点，并提供重置/菜单替代。以上是设计目标；Electron 窗口约束与实测单独验收。

## 6. 组件合同

精确 variant 轴与数量见 [token manifest](pioneer-design-tokens-v2.json) 的 `components`。14 个组件家族按“操作与字段 / 导航 / 工作台内容”组织，不堆在应用画板旁。

每个组件须有变量绑定、可编辑文本属性、适用状态、禁用原因与键盘说明。Button 覆盖 4 种语气×6种状态；输入、会话标签、局部标签、状态、海报、面板标题、上下文行、会话行、产物卡、权限卡、运行状态、验收、输入组合区各有独立状态，不能用一个万能空卡替代。

主家族 variant 不是全部行为的笛卡尔积。组合状态板须补充 hover/focus、只读字段、关闭按钮焦点、提交中、批准撤回/目标变更、空载错、版本冲突和对话框；非交互 Status 不要求 hover/disabled。开发稿逐项记录组件×业务状态×交互状态的覆盖与不适用理由，不能以“14 类已建”宣称全量状态验收。关闭控件作为内部构件单独维护，不计入 14 类主家族。

交付映射和不适用理由见[组件×状态交接矩阵](design-reset-handoff.md)。Status每个Tone使用独立文本属性，防止修改Error时覆盖Wait；实例内容与设计示例标签必须与业务状态一致。

- 按钮：动词+对象，焦点明显；loading保留动作含义，防止重复提交。
- 海报：名称、工作区身份、扫描时间；就绪、过期、路径不可用分开，失败不抹去原记录。
- 全局 Tab：标题优先，工作区与状态次之；关闭为独立操作；溢出从全部会话恢复。
- 输入：本机保存与模型发送是不同动作和回执；IME组合键不误提交；失败常驻。
- 权限：对象、路径、读/写/执行、后果、时效和拒绝同时可見；批准仅限本次。
- 产物：类型、标题、来源会话、版本、范围、打开动作；预览和验收指向同一版本。
- Diff：路径与真实版本，增删同时用符号/文本；不可读、二进制、过大、源失效分别说明。
- 对话框：标题、影响、取消、明确主动作；打开聚焦，关闭回到触发源。

## 7. 状态与内容

状态必须按“事实 → 影响 → 下一步”组织。会话、运行器连接、任务、保存、产物是五条独立状态轴，不合并成一个彩点。

| 情况     | 必须表达                               | 不允许                               |
| -------- | -------------------------------------- | ------------------------------------ |
| M2 草稿  | 已保存到本机；未发送给模型             | Agent正在回复、模拟工具调用伪装实况  |
| 待批准   | 正在等你的决定；本次对象和权限         | 换布局即批准、默认批准               |
| 停止请求 | 正在请求停止；等待确认                 | 按下按钮即显示已停止                 |
| 断连     | 最后确认事件；执行结果未知；重连后核对 | 自动重发、复用过期授权、把未知写失败 |
| 验收     | 未运行 / 运行中 / 真实通过 / 真实失败  | 预览成功即测试通过                   |
| 保存失败 | 保留未保存内容；重试/取消关闭          | 静默丢草稿、写入失败仍显示已保存     |

未来 M3/M4画板固定带“设计示例 · 运行器尚未接入”的可见标记；与 M2 本机开发稿分区，不混同当前能力。内容短而完整；不加人格口头禅作为风险或状态文案。

## 8. 无障碍与动效

正文至少4.5:1，大字和关键非文本边界至少3:1。[当前静态终审](design-reset-final-qa-2026-09-30.json)覆盖7个v2页面的1,697个文字节点及其实际实色背景；中文代码回退与1px描边几何例外逐项记录。文字色对通过不代表所有非文本边界、原型流程或运行时可访问性通过。状态不能只靠颜色。键盘覆盖建/切/关/恢复会话、字段、局部Tabs、布局、面板移动/恢复、分隔条、确认/拒绝；焦点返回有记录。读屏只公告有意义状态摘要，不逐token播报。

动效只表达反馈：hover/pressed约120ms，面板展开180ms，浮层160ms；这些是原创设计值，不是Claude测量值。降低动效模式取消位移，保留即时状态变化。不得用循环动画代替“等待谁/下一步”的文字。真实Windows高对比、200%缩放和读屏测试保持待验收。

## 9. 开发稿重置规则与完成标准

1. 先建 v2 规范与组件，再由实例组合新稿；旧 main/workbench 原节点完整保留，只在新稿通过后切换入口。
2. 主开发稿使用确定命名和分区：本机基线、未来运行、错误/边界、响应式；不把39张散落覆盖图当一张无限大主画布。
3. 每屏记录screenId、阶段、版本、状态、组件、跳转和验收；不随手改名导致交接失联。
4. 当前实现、设计覆盖、自动测试、人工实测分别记录；旧日志不变成新修订证据。
5. 完成要求：规范/Figma/token对应、全部计划组件和状态可编辑、开发稿按矩阵重置、旧稿可追溯、链接可用、截图和结构审计通过。P12实际点击、Electron工程验收与发布不由静态设计替代。
