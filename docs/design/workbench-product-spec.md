## 0. 权威、取材与适用范围

1. 当前全局视觉、字阶、组件与语义色以 [DESIGN-SYSTEM v2](DESIGN-SYSTEM.md) 和 [token manifest](pioneer-design-tokens-v2.json) 为准；本文负责信息架构、行为、数据、权限、响应式边界与验收。[旧交付索引](workbench-design-delivery.md)和旧 Figma workbench 保留为历史证据，不与 v2 并列决定外观。与旧演示不同时，以本规格的**后续实现合同**为准；重置交付状态另见 [交付表](development-reset.md)。
2. [Claude Desktop 官方证据与限制](references/claude-2026-09-28/DESKTOP.md)只提供参考：会话连续性、渐进展开工具、可审阅产物与显式权限。Claude 的三顶层入口、常驻侧栏、Mac 专属快捷功能、品牌资源及宣传页面 CSS **均不移植**。2026-09 Chat/Cowork 合并仍在分批推出，不能将历史演示帧当作当前 Windows 规范。
3. **范围内**：本地工作区库、会话 Tabs、任务对话、停靠模块、只读上下文、设置，以及后续 M3/M4 的能力/权限、意图核对、执行摘要、Diff/产物/验收、断连恢复。M2 的能力区只展示现有只读能力与不可用原因，不提供运行权限。**范围外**：已上线的云端/SSH/跨设备同步、自动合并/发布、无授权的本地写入、任意系统控制；这些不能从参考产品反推为 Pioneer 承诺。
4. M2 仅只读扫描和本机会话保存；运行、文件写入、模型调用和实际 Diff 在真实运行器接入、权限与测试前一律呈“不可用/尚未连接”，不得使用假成功态。M3/M4 条目是未来实现合同，不改变当前里程碑状态。

## 1. 信息架构与不变量

```text
窗口
├─ 唯一全局行：工作区库｜具体会话 Tabs（随宽度收纳，非硬上限）｜新会话｜全部会话｜设置
├─ 工作区库：海报、搜索、工作区概览、新建/继续会话
└─ 当前会话：标题/工作区身份｜专注/审阅/交付布局｜模块与布局操作
   ├─ Agent 对话（默认主轴；草稿/消息/审批/进度）
   └─ 可停靠面板（上下文、能力、改动、产物；产物内有局部 Tabs）
```

- **工作区 ≠ 会话 ≠ 标签 ≠ 任务运行 ≠ 产物**。一工作区可有多会话；关闭标签只从“打开集合”移除，会话记录仍在；关闭/切换/排列面板均不能开始、停止或授权任务。
- 全局“新会话”复用当前明确选择的工作区；尚未选工作区时禁用并给原因，或转到工作区选择，不隐式绑定任意目录。窄屏仍保留该入口，超出可见范围的标签从“全部会话”恢复。
- 一个会话持有独立草稿、消息、布局、当前产物视图与后续运行状态。任何会话间切换都不得串用草稿、权限卡、Diff、文件或运行器事件。
- 切布局只决定所见信息密度。专注以对话为先；审阅以对话与 Diff/证据并列；交付以产物与对话并列。**不存在第二排全局导航或常驻历史侧栏**。
- 凡声称“已执行/已写入/已通过”，界面须能指出真实事件或验证证据；推断、计划、模拟和缓存各有标签，不混为一谈。

## 2. 视觉与内容合同

以下配色是融合基线摘要，不是第二套 token 权威；新增功能边界、深色状态文字及精确尺寸均以 [v2 §3–6](DESIGN-SYSTEM.md) 为准。应用现有 CSS 与 v2 设计值的差异单独登记，不因本表而覆盖新规范。

| 角色             | 规范                                        | 使用限制                                                 |
| ---------------- | ------------------------------------------- | -------------------------------------------------------- |
| 画布/面板        | `#F1F2EE` / `#F9FAF7`                       | 大面积保持中性；通过间距与细边界分层                     |
| 主文/次文        | `#2C3547` / `#646E72`                       | 正文不使用低对比香槟字；次文不能承载唯一关键信息         |
| 主操作/按钮字    | `#333C50` / `#F9F9F9`                       | 一个决策区域通常仅一个主动作                             |
| 边界/身份        | `#D3D3D3`；工作区辅助色 `#DDE2E9/#DCEADF`   | 身份色不表示权限或运行状态                               |
| 待处理/成功/危险 | `#EDE4D6`+`#C6AF94` / `#D7E3DA` / `#B25352` | 必须同时有文字和可识别动作；红色不用于普通失败以外的强调 |

已有 CSS 变量见 [`tokens.css`](../../apps/desktop/src/renderer/styles/tokens.css)，它尚未与v2同步。`#76614B` 在 `#C6AF94` 实心底上约 2.78:1，不作为小字组合；香槟底使用主文。中文优先 Noto Sans SC，拉丁 Inter，代码 JetBrains Mono（中文范围回退 Noto Sans SC）。UI 标题20–24px，正文14–15px；12px辅助信息不得独自承载审批范围、风险和错误原因。间距0/4/8/12/16/24/32/48/64px；按钮8px、面板12px、输入组合区16px圆角。次文色只用于surface/canvas；surface-muted或身份色上的文字使用主文色，不能照搬旧浅灰文案。不新增Claude品牌橙/专有字体、玻璃、渐变或营销式巨幅标题。

**状态文案结构**：状态（现在发生什么）→ 影响（哪些内容/范围）→ 下一步（用户能做什么）。例如“连接中断。执行是否继续尚未确认；先重新连接并核对记录”，而不是“出错了”。按钮使用动词+对象：`批准本次写入`、`拒绝并保留讨论`、`重新读取`。危险或不可逆动作写明对象数量/路径与撤销可能性，禁用项说明原因。

## 3. 窗口、密度与响应式

以下尺寸是**设计验收目标**，不是“已测过”的断言。基于当前代码 `.app-shell` 640px CSS 最小宽、DockSurface `<760px` 收纳、双栏每栏至少约 320px 的事实制定；Electron 窗口目前未设置原生 minSize，不能靠 CSS 最小宽冒充系统窗口约束。

| 可用内容宽/窗口样本        | 布局决定                                                                      | 必须验证                                                    |
| -------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------- |
| ≥1440px，1440×900          | 最多 5 个显性会话标签；可双栏；对话阅读列上限约 840px；产物按布局并列         | 长标题截断且全名可取，固定输入区，面板各自滚动              |
| 1001–1439px，1280×800      | 最多 3 个显性会话标签，其余“全部会话”；双栏仅在两侧 ≥320px 时出现             | 拖动/缩放上下限、审批卡不被输入框遮住                       |
| 760–1000px，建议测 900×700 | 工具栏允许换行，双栏可用但不保证；非关键面板可临时收起并保留显式入口          | 所有控件可达，局部 Tabs 横向内容不丢失                      |
| 640–759px，建议测 640×720  | 单列优先保留对话+输入；额外面板进入“展开面板”临时视图，不自动永久改变保存布局 | 零横向裁切；展开/关闭后焦点返回入口；草稿与滚动位置合理     |
| 高度 ≤600px 或 200% 缩放   | 导航/输入不遮挡审批、错误和面板入口；内容区域各自滚动；必要时只显示最小工具栏 | 不因高 DPI 或缩放丢失主操作；原生窗口最小值需另行设定和验证 |

分栏手柄的可视线可以窄，但交互命中区与键盘焦点不得只剩 3px；比例限定必须保护对话最小可用宽和输入区。空间不足时“暂时收起”优先级：对话与待用户处理 > 当前审阅产物 > 上下文/能力；收起不等于永久关闭。布局保存是**按会话、按布局模式**的用户动作；保存中、失败、成功分别显示，失败不得写“已保存”。

## 4. 独立状态轴与转移

### 4.1 状态轴（不得压成一个彩色圆点）

| 轴         | 状态                                                                                                 | 界面必须给出                                                              |
| ---------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 会话记录   | 未创建 / 打开 / 标签已收起但保留 / 归档（未来）                                                      | “全部会话”能恢复；删除/归档须另有独立动作与确认                           |
| 运行器连接 | 未配置 / 连接中 / 可用 / 断连 / 权限受限                                                             | 是否可发送；最后确认时间；重试/配置入口；未知执行状态不可伪装为失败或已停 |
| 任务       | 草稿 / 待启动 / 运行中 / 等待说明 / 待批准 / 停止请求中 / 已停止 / 待审阅 / 已完成 / 失败 / 结果未知 | 当前责任人、最新已确认事件、下一步；等待与运行不可用同一文案              |
| 保存       | 未改 / 本机保存中 / 已保存 / 保存失败                                                                | 失败常驻且可重试；未落盘前关闭窗口需按关闭协议处理                        |
| 产物       | 未生成 / 生成中 / 可预览 / 版本更新中 / 验证中 / 已验证 / 验证失败 / 来源失效                        | 类型、来源会话/任务、文件路径或安全句柄、版本/时间、真实验证记录          |

M2 当前仅可出现会话草稿/保留、运行器未连接、只读项目和空产物；不要为了展示未来状态而给用户伪运行指示。状态标签是“当前事实”而非从颜色、布局或隐藏面板推断。

### 4.2 关键转移与否决

| 事件                 | 前置与结果                                                                             | 不能发生                                                |
| -------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 新建/恢复/关闭标签   | 新建绑定一个工作区；恢复既有会话原草稿/布局；关闭仅移除 Tab，未发送草稿需提醒          | 关闭＝删除，切会话＝结束运行                            |
| 提交任务（M3+）      | 运行器可用 + 可明确目标；创建任务 ID，输入进入已提交记录                               | M2 将本机“保存消息”说成已发给模型                       |
| 意图核对/批准（M3+） | 展示目标、将读写的资源、拟执行步骤、权限范围与到期；用户批准**本次操作**后记录授权事件 | 打开布局/面板＝授权；重试时静默复用旧批准；拒绝后仍执行 |
| 停止                 | 运行中→停止请求中→收到运行器确认后已停止；超时/断连显示“结果未知”                      | 点击停止瞬间写“已停止”；把断连当成停止                  |
| 断连恢复             | 标记最后已确认事件；重新连接后核对 taskId、权限与事件序列，再恢复可行操作              | 自动重新执行未知动作；丢掉待审阅结果；放大旧权限        |
| 审阅与交付           | 逐文件 Diff/产物打开→人工审阅→真正验收结果；发布/外发另需独立授权                      | 测试未跑就标“通过”；预览即写入；分享即发布              |
| 保存失败/窗口关闭    | 失败常驻、重试；窗口关闭等待已受理写入或提供明确未保存后果                             | 静默丢草稿或布局、以 UI 消失作为落盘证据                |

### 4.3 本机数据、删除与冲突

**当前事实**：`session-state-store.ts` 将会话标题、草稿、已保留消息、布局等作为带版本号的 JSON 明文写到 Electron `userData/pioneer-session-state.json`；序列化写入有临时文件替换与尺寸/结构校验。当前上限为每会话 100 条消息、单条消息/草稿 8000 字符、整份会话状态 8 MiB；触顶时必须说明不能继续保存的原因与下一步，不可静默截断或自动清掉旧记录。它不是加密保险箱，不宜粘贴密码或密钥。M2 当前“保存到会话”**只在本机**，未发送给模型；未来真实模型接入时，首次提交前必须显示所选 Provider、将发送的内容/附件范围，并与本机保存明确区分。产品不得宣称“端到端加密”或“云端同步”。

**保留与用户控制（产品完成门禁，尚非现有能力）**：默认会话记录留在本机，直到用户明确删除；关闭 Tab 和未来归档都不是删除。设置页需能查看数据位置/内容类别，提供导出本机会话的安全流程，以及“删除一段会话/清空全部会话”的独立动作。删除确认需写会话名、记录/草稿/布局范围、不可由应用内恢复的后果，并提供取消；清空全部需更强二次核对。导出前提示文件可能包含敏感内容；导出不可静默上传。成功后才从 UI 和应用存储中移除；操作系统备份/已外发给模型的内容不在本机删除范围，需明确说明。当前版本没有这些入口，不能以关闭标签代替。

**坏档/版本迁移**：读取失败或记录格式不受支持时停止写入该文件并保留原件；给出重试、查看位置/诊断、受控恢复/重置三个不同入口。重置前必须提供可恢复副本或显式告知无法恢复，不能为“重新开始”静默覆盖旧 JSON。每次格式升级须有向前迁移与失败回退的测试；旧版文件不因新版本启动而自动丢弃。保存失败常驻；“放弃本次未保存内容并关闭”须独立确认，只影响未落盘增量。

**工作区与文件冲突**：扫描结果标采集时间；根目录失联/移动时保留原记录和路径提示，不把同名新目录悄悄绑定到旧会话。部分扫描可展示已知内容但要标“可能过期”。未来写入/覆盖必须在执行前展示目标路径、前后差异与最新磁盘版本；若批准后目标被外部修改，旧批准失效，重新核对。二进制/过大/不可读文件用受限预览与明确原因，不能显示伪空 Diff。

## 5. 核心组件行为合同

每个组件都必须覆盖 `idle / hover / focus-visible / disabled（说明原因） / loading / error` 中相关状态；无真实数据时显示明确空态，不能用占位信息伪装实绩。

| 组件             | 最小可见内容与动作                                                                | 语义/键盘/边界                                                                                                                              |
| ---------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 工作区海报       | 名称、身份色/图形、只读元数据摘要、继续/新会话；扫描时间或失败原因                | 整卡可操作但不嵌套冲突按钮；空库、不可访问路径、部分扫描、扫描失败有区别                                                                    |
| 全局会话 Tab     | 任务名优先，工作区与状态次之；关闭独立、溢出可搜索；重排不改会话 ID               | `tablist/tab/tabpanel`，方向键/Home/End、Tab 离开、焦点在关闭后落到合理邻居；重排有键盘替代。当前 `TabStrip.tsx` 已有部分实现，仍需读屏实测 |
| 全部会话         | 标题/工作区/是否有草稿/是否打开、搜索与恢复；未来运行状态可筛选                   | 模态聚焦/关闭返回；搜索空结果与无会话空态不同；不新增常驻历史栏                                                                             |
| 对话与输入       | 消息来源、是否已发送/仅本机保存、时间/执行关联；输入、附件/能力入口仅在可用时展示 | `Ctrl+Enter` 提交、IME 组合键不误发；发送中禁重复；焦点不被流式内容抢走；滚动不强制打断上翻审阅                                             |
| 任务状态/事件    | 状态文字、最后已确认时间、阶段摘要、等待谁、下一步；详情按需展开                  | 更新以 `role=status` 摘要公告而非逐 token 播报；未知态醒目且可核对                                                                          |
| 权限/意图卡      | 本次动作、目标路径/域、读/写/执行类型、影响、可撤销性、时效；批准/拒绝            | 默认不授权；危险动作不能用模糊“继续”；拒绝后卡片保留决定记录；权限与运行器强制校验一致                                                      |
| Dock 面板        | 标题、当前面板状态、拖动/移动/收起菜单；不可见面板显式可恢复                      | 拖放非唯一方式：菜单可移左/右/前/后；分隔条方向键/Home/End；Escape 可取消拖动；收起后焦点有去处                                             |
| 局部 Tabs / 产物 | `预览 / 文件清单 / 验收记录` 只改变产物面板；各自有加载/空/部分/失败/就绪         | 独立 `tablist`；切换不影响全局会话、任务或授权；文件/预览必须指向同一产物版本                                                               |
| Diff 与验收      | 改动数、逐文件列表、前/后内容、路径与来源；验收有命令/时间/退出码/范围            | 只读先行；无法读取、二进制、过大、权限不足时给替代说明；不能仅凭颜色表示增删                                                                |
| 设置/能力        | 当前能力、连接状态、来源/范围、启停和配置入口；会话入口显示当前使用能力           | 全局设置不等于本次任务授权；连接失败可重试、需登录或不可用分别显示                                                                          |
| 通知/对话框      | 原因、影响、可执行下一步；危险确认指出对象与后果                                  | 聚焦陷入模态、Esc 只关闭可取消弹窗、关闭返回触发源；不可用时不丢键盘焦点                                                                    |

### 5.1 状态矩阵：同一组件不能用一张“万能空卡”

表内执行、权限、真实 Diff/产物属于 M3/M4 的设计目标；M2 只允许只读数据、明确不可用与空态。

| 区域      | 空/未配置                                             | 加载/进行中                                                                    | 部分/过期/等待                                             | 失败/断连                                                         | 就绪                                                   |
| --------- | ----------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------ |
| 工作区库  | `还没有工作区` + 选择目录；不显示虚构项目             | `正在读取工作区` + 当前目录；扫描期间禁用重复选择/刷新，避免并发扫描与状态竞态 | 显示已知海报并标扫描时间、警告数、`重新读取`               | 保留上次成功数据并标“可能过期”；路径失效给 `更换目录`，不清空会话 | 海报、扫描时间、可进入概览                             |
| 会话输入  | 空草稿仍可本机输入；运行器未接时主动作叫 `保存到会话` | M3 发送中提供停止/排队策略，不允许重复提交同一输入                             | 等待用户说明或批准时明确“你的决定”，草稿不因等待消失       | 本机保存失败给重试；模型断连给核对/重连，不自动重发               | 已保存或真实已提交须有两种不同回执                     |
| 能力/权限 | `未连接运行器`、现有只读能力；执行/写入注明未授权     | 连接中列当前对象与取消/返回                                                    | 只允许已知作用域；过期批准回待核对                         | 登录/连接失败指出影响的能力和重试入口                             | 已启用能力、来源、当前任务可用范围；危险动作仍逐次核对 |
| Diff/文件 | `还没有可审阅的改动`，不预填样本                      | 显示正在读取的文件数与可取消状态                                               | 部分文件可预览，失败文件逐项标原因；磁盘版本变化需重新核对 | 不可读/过大/二进制/源失效分类说明，不用空白面板吞错               | 文件数、增删概览、前后内容、来源版本                   |
| 产物/验收 | `尚未生成` / `尚未执行验收` 分开写                    | 生成与验证分别报阶段，不提前标通过                                             | 有产物但待审阅或测试尚未确认；导出禁用时解释原因           | 验证失败呈真实命令/退出码/失败范围；断连保持最后确认结果          | 预览、文件清单、验收记录指向相同版本                   |
| 本机记录  | 尚无记录不等于坏档                                    | 保存中禁“已保存”措辞                                                           | 关闭等待已受理写入；用户可取消关闭                         | 错误常驻、重试；坏档禁止静默覆盖                                  | 成功落盘后才能显示 `已保存`                            |

空态、加载态和错误态均需短句而非插画占位。图标可辅助，但可见文本必须独立表达状态。每条操作反馈须可被读屏取得，同时避免把流式过程逐字广播。

## 7. 可访问性与平台适配验收

目标为 [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) 对 Electron 渲染内容的适用条款；Tabs、模态与可调整分隔条遵循 W3C [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)、[Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)、[Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) 模式。**这是一项目标，不是当前符合性声明。**

- 正文字色至少 4.5:1；大字至少 3:1；非文本关键边界/焦点至少 3:1。状态不能只靠颜色。逐组量测，不能以已有三组配色的计算结果覆盖所有组件。
- 键盘必须完成：建/切/关/恢复会话、改名、搜索、三布局、面板移动/收起/恢复/缩放、输入、批准/拒绝/停止、逐文件审阅。每步有可见焦点；切页面、关模态、临时展开结束后焦点到逻辑触发点。无键盘陷阱。
- 可见控件目标以 ≥32×32 CSS px 为默认；若使用更小紧凑按钮，至少满足 WCAG 2.2 的 24×24px 或间距例外，并记录原因。高对比/Windows 强制颜色、200% 缩放、`prefers-reduced-motion` 需实测。动效仅用于状态/层级反馈，不让等待动画代替文字。
- Windows 原生文件夹选择器、系统托盘/快捷键若未来实现，必须有平台特定设计与人工验证；不从 Mac 视频移植快捷键。原生选择器不在当前确定性 E2E fixture seam 内。

## 9. 本规格自身的变更规则

新增能力先回答：属于哪一会话/任务、何时可见、没有权限怎么办、断连如何恢复、结果如何证明、窄窗口怎样收纳、键盘怎样到达。答不全不得只增一张“好看”的卡片。每次修改同步更新对应 Figma 节点、组件状态、代码引用和验收用例；失效的 Claude 参考要标日期而非静默当作恒定事实。
